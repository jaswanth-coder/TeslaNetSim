1.1 Discrete-Event Simulation (DES) vs. Real-World Wall-Clock Time

In everyday programming (such as web servers or game engines), time advances continuously according to the CPU wall-clock stopwatch ($\Delta t = 16.6\text{ ms}$ for 60 frames per second). In contrast, ns-3 is a Discrete-Event Simulator (DES).

⏱️ Visual Flow: Discrete Event Priority Queue & Clock Leaps

Figure 1.1: The event priority queue calendar. When the calendar executes $t=2.002\text{s}$, it immediately leaps forward to the next scheduled event without wasting wall-clock CPU instructions.

  • The Event Calendar: A priority queue $Q$ sorted strictly by timestamp $t$.
  • Zero Idle Latency: If no events are scheduled between $2.002\text{s}$ and $10.0\text{s}$, the simulator advances virtual time instantaneously.

1.2 The Standard 7-Step Simulation Pipeline

Whether you are building a simple 2-node point-to-point link or a 100-node IEEE 802.11be WiFi 7 Multi-Link network, every ns-3 simulation follows seven standardized phases.

🔄 Visual Pipeline: The 7-Step Sequence Flow
1
CLI Argument Parsing CommandLine cmd; cmd.Parse(argc, argv);
Allows overriding simulation parameters directly from the shell terminal without re-compiling C++ source.
2
Node Creation NodeContainer nodes; nodes.Create(2);
Instantiates bare virtual computing hosts managed by intrusive reference counting smart pointers (Ptr<Node>).
3
Device & Channel Configuration PointToPointHelper p2p; NetDeviceContainer dev = p2p.Install(nodes);
Models the physical medium (cable/wireless channel) and installs Network Interface Cards (NICs) on nodes.
4
Protocol Stack Installation InternetStackHelper stack; stack.Install(nodes);
Aggregates ARP, IPv4/IPv6, ICMP, UDP, and TCP protocol engines into each bare node object.
5
IP Address Assignment Ipv4AddressHelper ip; ip.Assign(dev);
Allocates network subnets, sets netmasks, binds IP addresses to NIC interfaces, and configures loopbacks.
6
Application Setup & Scheduling UdpEchoServerHelper / UdpEchoClientHelper
Binds listener sockets on destination ports and schedules traffic generation start and stop events.
7
Execution & Memory Teardown Simulator::Run(); Simulator::Destroy();
Starts the priority queue event calendar loop and cleanly frees cyclic references to prevent memory leaks.

2.1 The Core Network Abstraction Trifecta: Node, NetDevice & Channel

In physical networking, communication requires three physical entities: a computing computer, a network card interface (NIC), and an interconnecting cable or wireless medium. In ns-3, these map directly to three primary C++ abstractions:

  • Logical Host (Ptr<Node>): Represents a network host, router, switch, or mobile station. Crucially, a Node begins as a completely "blank slate" (no NICs, no IP stack, no apps). Layers must be explicitly attached via the object aggregation system.
  • Network Interface Card (Ptr<NetDevice>): Models the hardware NIC, link-layer drivers, MAC headers, framing logic, and transmission queues (e.g. PointToPointNetDevice, CsmaNetDevice, WifiNetDevice). A single node can hold multiple NetDevices to connect to multiple networks.
  • Physical Medium (Ptr<Channel>): Represents the transmission medium (fiber optics, coaxial cable, or wireless radio propagation environment). A NetDevice plugs into a Channel to propagate signals.

Figure 2.1: The ns-3 Object Aggregation Model. Rather than using rigid multiple inheritance, protocols are aggregated to the Node at runtime. Any component queries them via node->GetObject<T>().

Complete Executable C++ Gateway Script (two-subnet-router.cc)

#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"

using namespace ns3;

NS_LOG_COMPONENT_DEFINE ("TwoSubnetRouter");

int main (int argc, char *argv[])
{
  CommandLine cmd (__FILE__);
  cmd.Parse (argc, argv);

  Time::SetResolution (Time::NS);
  LogComponentEnable ("UdpEchoClientApplication", LOG_LEVEL_INFO);
  LogComponentEnable ("UdpEchoServerApplication", LOG_LEVEL_INFO);

  // STEP 1: Allocate 3 Nodes (Node 0 = Client, Node 1 = Router, Node 2 = Server)
  NodeContainer nodes;
  nodes.Create (3);

  // Group pairs for two distinct point-to-point links
  NodeContainer netA = NodeContainer (nodes.Get (0), nodes.Get (1));
  NodeContainer netB = NodeContainer (nodes.Get (1), nodes.Get (2));

  // STEP 2: Configure Point-to-Point Links
  PointToPointHelper p2p;
  p2p.SetDeviceAttribute ("DataRate", StringValue ("10Mbps"));
  p2p.SetChannelAttribute ("Delay", StringValue ("5ms"));

  NetDeviceContainer devicesA = p2p.Install (netA);
  NetDeviceContainer devicesB = p2p.Install (netB);

  // STEP 3: Install Internet Protocol Stack on all nodes
  InternetStackHelper stack;
  stack.Install (nodes);

  // STEP 4: Assign Subnet 1 (192.168.1.0/24)
  Ipv4AddressHelper address;
  address.SetBase ("192.168.1.0", "255.255.255.0");
  Ipv4InterfaceContainer interfacesA = address.Assign (devicesA);

  // Assign Subnet 2 (192.168.2.0/24)
  address.SetBase ("192.168.2.0", "255.255.255.0");
  Ipv4InterfaceContainer interfacesB = address.Assign (devicesB);

  // STEP 5: Populate Global Routing Tables (CRUCIAL for Gateway Forwarding)
  Ipv4GlobalRoutingHelper::PopulateRoutingTables ();

  // STEP 6: Configure Server on Node 2 (Listening on Port 9)
  UdpEchoServerHelper echoServer (9);
  ApplicationContainer serverApps = echoServer.Install (nodes.Get (2));
  serverApps.Start (Seconds (1.0));
  serverApps.Stop (Seconds (10.0));

  // Configure Client on Node 0 targeting Node 2 across the gateway
  UdpEchoClientHelper echoClient (interfacesB.GetAddress (1), 9); // 192.168.2.2
  echoClient.SetAttribute ("MaxPackets", UintegerValue (3));
  echoClient.SetAttribute ("Interval", TimeValue (Seconds (1.0)));
  echoClient.SetAttribute ("PacketSize", UintegerValue (1024));

  ApplicationContainer clientApps = echoClient.Install (nodes.Get (0));
  clientApps.Start (Seconds (2.0));
  clientApps.Stop (Seconds (10.0));

  // STEP 7: Run Simulation & Clean Up Memory
  Simulator::Run ();
  Simulator::Destroy ();

  return 0;
}

2.4 Line-by-Line Architectural Dissection of the Gateway Script

Code Statement Exhaustive Architectural Breakdown (What, Why & Memory Model)
NodeContainer nodes;
nodes.Create (3);		 What: Allocates three bare host computers in memory.
Why: Models the client (Node 0), the intermediary gateway router (Node 1), and the destination server (Node 2).
Under the Hood: Three distinct Ptr<Node> smart pointers are instantiated via CreateObject<Node>() with empty aggregation registries.
NodeContainer netA = NodeContainer (nodes.Get(0), nodes.Get(1));
NodeContainer netB = NodeContainer (nodes.Get(1), nodes.Get(2));		 What: Creates two separate sub-containers grouping adjacent nodes into physical links.
Why: A point-to-point helper can only install across two nodes at a time. Grouping them cleanly isolates Link A from Link B.
Under the Hood: Notice that nodes.Get(1) is added to both containers! This increments Node 1's reference counter, allowing it to bridge the two networks.
NetDeviceContainer devicesA = p2p.Install(netA);
NetDeviceContainer devicesB = p2p.Install(netB);		 What: Installs two separate physical links and four NICs in total.
Why: Link A creates a PointToPointChannel between Node 0 and Node 1. Link B creates an independent PointToPointChannel between Node 1 and Node 2.
Under the Hood: Node 1 now contains two distinct NetDevice objects inside its internal device array: m_devices[0] connected to Link A and m_devices[1] connected to Link B!
address.SetBase ("192.168.1.0", ...);
Ipv4InterfaceContainer interfacesA = address.Assign(devicesA);
address.SetBase ("192.168.2.0", ...);
Ipv4InterfaceContainer interfacesB = address.Assign(devicesB);		 What: Configures two separate IP subnets: 192.168.1.0/24 and 192.168.2.0/24.
Why: Prevents IP subnet conflicts. Node 0 receives 192.168.1.1; Node 1 receives 192.168.1.2 on Interface A and 192.168.2.1 on Interface B; Node 2 receives 192.168.2.2.
Under the Hood: Node 1 is now a multi-homed router with two entries in its internal Ipv4Interface table.
Ipv4GlobalRoutingHelper::PopulateRoutingTables (); What: Automatically builds routing tables for all nodes in the simulation.
Why: MANDATORY FOR MULTI-HOP COMMUNICATION! Without this call, Node 0 has no idea where subnet 192.168.2.0/24 lives, and its IP engine will drop all outbound packets as unroutable.
Under the Hood: Runs Dijkstra's shortest-path algorithm across all channels. It inserts a routing table entry on Node 0 stating: "To reach 192.168.2.0/24, send to gateway 192.168.1.2 via dev 0", and configures Node 1 to forward packets between Interface 0 and Interface 1.
UdpEchoClientHelper echoClient (interfacesB.GetAddress (1), 9); What: Directs the UDP client on Node 0 to send packets to Node 2's IP address (192.168.2.2).
Why: interfacesB.GetAddress(1) queries the second device of Link B, which belongs to Node 2.
Packet Path: Node 0 (192.168.1.1) $\to$ Cable A (5ms) $\to$ Node 1 (Router forwards) $\to$ Cable B (5ms) $\to$ Node 2 (Server responds) $\to$ Round-Trip Time = 20 ms!

3.1 The ns-3 Logging Subsystem & Severity Hierarchy

In production network simulators, writing standard console print statements (such as std::cout << "...") is considered bad engineering practice. Console I/O slows down execution, clutters standard output during multi-run parameter sweeps, and cannot be filtered without modifying and recompiling the source code.

ns-3 solves this with a robust, granular Logging Subsystem organized into seven distinct severity levels.

🔊 Visual Architecture: The ns-3 Logging Severity Pyramid

Figure 3.1: The Severity Pyramid. Enabling any level automatically cascades to include all higher-severity messages above it. For example, selecting LOG_LEVEL_INFO includes LOG_INFO, LOG_DEBUG, LOG_WARN, and LOG_ERROR.

Tip
 The Volume Switch Analogy: Think of logging in ns-3 like a volume knob on a receiver. When turned low (LOG_ERROR), you only hear catastrophic sirens (panics). When turned to maximum (LOG_ALL), you hear every footstep, breath, and function call execution. In optimized build profiles, all debug logs are automatically compiled out to guarantee maximum simulation speed.

When conducting research sweeps (e.g. testing packet delivery rates across payload sizes from 64 to 1500 bytes), you must never hardcode variables. ns-3 provides a unified pipeline that binds command-line tokens to class attributes:

3.3 Complete Canonical Tweaking Script (tweaking-demo.cc)

Below is a complete, fully functional script illustrating how to define custom logging identifiers, track function entry/exit points, bind dynamic command-line variables, and tweak attributes: 

#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"
#include <iostream>

using namespace ns3;

// STEP 1: Define unique logging component identifier
NS_LOG_COMPONENT_DEFINE ("AeroWlanTweakingDemo");

// Helper function demonstrating automatic parameter tracing
void ComputeSyntheticMetrics (uint32_t packetSize, double delayMs)
{
  NS_LOG_FUNCTION (packetSize << delayMs);
  NS_LOG_INFO ("Computing transmission time for payload of " << packetSize << " bytes");
  if (packetSize > 1500) {
    NS_LOG_WARN ("Packet size exceeds standard Ethernet MTU (1500 bytes)! Fragmentation will occur.");
  }
}

int main (int argc, char *argv[])
{
  // STEP 2: Configure default variable values
  uint32_t nPackets = 5;
  uint32_t packetSize = 1024;
  std::string dataRate = "10Mbps";
  bool verbose = true;

  // STEP 3: Register variables with the CommandLine parser
  CommandLine cmd (__FILE__);
  cmd.AddValue ("nPackets", "Total number of UDP packets to transmit", nPackets);
  cmd.AddValue ("packetSize", "Size of packet payload in bytes", packetSize);
  cmd.AddValue ("dataRate", "Bandwidth data rate of the point-to-point link", dataRate);
  cmd.AddValue ("verbose", "Enable informational console logging", verbose);
  cmd.Parse (argc, argv);

  // STEP 4: Conditionally configure logging levels
  if (verbose) {
    LogComponentEnable ("AeroWlanTweakingDemo", LOG_LEVEL_ALL);
    LogComponentEnable ("UdpEchoClientApplication", LOG_LEVEL_INFO);
    LogComponentEnable ("UdpEchoServerApplication", LOG_LEVEL_INFO);
  }

  NS_LOG_INFO ("--- Starting Simulation Initialization ---");

  // Call sample function to see automatic parameter trace
  ComputeSyntheticMetrics (packetSize, 2.0);

  // STEP 5: Globally tweak defaults via Config subsystem
  Config::SetDefault ("ns3::PointToPointNetDevice::Mtu", UintegerValue (1500));

  NodeContainer nodes;
  nodes.Create (2);

  PointToPointHelper p2p;
  p2p.SetDeviceAttribute ("DataRate", StringValue (dataRate));
  p2p.SetChannelAttribute ("Delay", StringValue ("2ms"));

  NetDeviceContainer devices = p2p.Install (nodes);

  InternetStackHelper stack;
  stack.Install (nodes);

  Ipv4AddressHelper address;
  address.SetBase ("10.1.1.0", "255.255.255.0");
  Ipv4InterfaceContainer interfaces = address.Assign (devices);

  UdpEchoServerHelper server (9);
  ApplicationContainer serverApps = server.Install (nodes.Get (1));
  serverApps.Start (Seconds (1.0));
  serverApps.Stop (Seconds (10.0));

  UdpEchoClientHelper client (interfaces.GetAddress (1), 9);
  client.SetAttribute ("MaxPackets", UintegerValue (nPackets));
  client.SetAttribute ("Interval", TimeValue (Seconds (1.0)));
  client.SetAttribute ("PacketSize", UintegerValue (packetSize));

  ApplicationContainer clientApps = client.Install (nodes.Get (0));
  clientApps.Start (Seconds (2.0));
  clientApps.Stop (Seconds (10.0));

  NS_LOG_INFO ("--- Entering Simulator::Run() Event Loop ---");
  Simulator::Run ();
  Simulator::Destroy ();
  NS_LOG_INFO ("--- Simulation Successfully Finished ---");

  return 0;
}

Why: Enables runtime toggling of this file's log statements from the shell via export NS_LOG="AeroWlanTweakingDemo=level_all" without altering or recompiling source code.
Under the Hood: Registers an instance of LogComponent inside ns-3's global static logging map.

Why: Eliminates manual debugging print statements. If LOG_FUNCTION is enabled, it prints: "AeroWlanTweakingDemo:ComputeSyntheticMetrics(1024, 2)".

NS_LOG_WARN ("Packet size exceeds MTU..."); What: Logs a warning condition of medium-high severity.

3.5 Terminal Command Cheatsheet for Tweaking & Inspection

4.3 Canonical C++ Script (second.cc)

#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/csma-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"
#include "ns3/ipv4-global-routing-helper.h"

using namespace ns3;

NS_LOG_COMPONENT_DEFINE ("SecondScriptExample");

int main (int argc, char *argv[])
{
  bool verbose = true;
  uint32_t nCsma = 3;

  CommandLine cmd (__FILE__);
  cmd.AddValue ("nCsma", "Number of extra CSMA nodes", nCsma);
  cmd.AddValue ("verbose", "Tell echo applications to log if true", verbose);
  cmd.Parse (argc, argv);

  if (verbose) {
    LogComponentEnable ("UdpEchoClientApplication", LOG_LEVEL_INFO);
    LogComponentEnable ("UdpEchoServerApplication", LOG_LEVEL_INFO);
  }

  // STEP 1: Allocate P2P Nodes (Node 0 and Node 1)
  NodeContainer p2pNodes;
  p2pNodes.Create (2);

  // STEP 2: Allocate CSMA Nodes & SHARE Node 1
  NodeContainer csmaNodes;
  csmaNodes.Add (p2pNodes.Get (1)); // Node 1 joins the CSMA LAN!
  csmaNodes.Create (nCsma);          // Creates Node 2, Node 3, and Node 4

  // STEP 3: Setup Point-to-Point Link
  PointToPointHelper pointToPoint;
  pointToPoint.SetDeviceAttribute ("DataRate", StringValue ("5Mbps"));
  pointToPoint.SetChannelAttribute ("Delay", StringValue ("2ms"));
  NetDeviceContainer p2pDevices = pointToPoint.Install (p2pNodes);

  // STEP 4: Setup CSMA Bus Channel
  CsmaHelper csma;
  csma.SetChannelAttribute ("DataRate", StringValue ("100Mbps"));
  csma.SetChannelAttribute ("Delay", TimeValue (NanoSeconds (6560)));
  NetDeviceContainer csmaDevices = csma.Install (csmaNodes);

  // STEP 5: Install Internet Stack
  InternetStackHelper stack;
  stack.Install (p2pNodes.Get (0)); // Install on Node 0
  stack.Install (csmaNodes);        // Installs on Node 1, 2, 3, 4 (Node 1 only once!)

  // STEP 6: Assign IP Addresses to Both Subnets
  Ipv4AddressHelper address;

  // Subnet 1 (P2P): 10.1.1.0/24
  address.SetBase ("10.1.1.0", "255.255.255.0");
  Ipv4InterfaceContainer p2pInterfaces = address.Assign (p2pDevices);

  // Subnet 2 (CSMA): 10.1.2.0/24
  address.SetBase ("10.1.2.0", "255.255.255.0");
  Ipv4InterfaceContainer csmaInterfaces = address.Assign (csmaDevices);

  // STEP 7: Populate Global Routing Tables
  Ipv4GlobalRoutingHelper::PopulateRoutingTables ();

  // STEP 8: Configure Server on Node 0 (Listening on Port 9)
  UdpEchoServerHelper echoServer (9);
  ApplicationContainer serverApps = echoServer.Install (p2pNodes.Get (0));
  serverApps.Start (Seconds (1.0));
  serverApps.Stop (Seconds (10.0));

  // Configure Client on Node 4 (Last CSMA node) targeting Node 0's IP
  UdpEchoClientHelper echoClient (p2pInterfaces.GetAddress (0), 9);
  echoClient.SetAttribute ("MaxPackets", UintegerValue (1));
  echoClient.SetAttribute ("Interval", TimeValue (Seconds (1.0)));
  echoClient.SetAttribute ("PacketSize", UintegerValue (1024));

  ApplicationContainer clientApps = echoClient.Install (csmaNodes.Get (nCsma));
  clientApps.Start (Seconds (2.0));
  clientApps.Stop (Seconds (10.0));

  // Enable PCAP Traces on the Gateway to capture packet forwarding
  pointToPoint.EnablePcapAll ("second");
  csma.EnablePcap ("second", csmaDevices.Get (1), true);

  Simulator::Run ();
  Simulator::Destroy ();
  return 0;
}

csmaNodes.Create (nCsma);		 What: Adds existing Node 1 into the CSMA container, then allocates 3 fresh nodes (Nodes 2, 3, 4).
Why: Crucial for Bridging! Node 1 is the physical bridge connecting the P2P wire to the CSMA bus.
Under the Hood: csmaNodes.Get(0) references the exact same Ptr<Node> in memory as p2pNodes.Get(1). Its reference count increases to 2!
csma.SetChannelAttribute ("Delay", TimeValue (NanoSeconds (6560))); What: Configures propagation delay across the shared bus to 6560 nanoseconds.
Why: In copper cable, electrical signals propagate at approximately $\frac{2}{3}$ the speed of light ($200,000\text{ km/s}$). A delay of $6560\text{ ns}$ accurately models signal propagation across a standard 1.3 kilometer Ethernet segment!
stack.Install (p2pNodes.Get (0));

Why: Calling stack.Install(p2pNodes) followed by stack.Install(csmaNodes) would attempt to install IPv4 onto Node 1 twice, causing a fatal assertion panic. Explicitly targeting p2pNodes.Get(0) first avoids this crash!
Ipv4GlobalRoutingHelper::PopulateRoutingTables (); What: Calculates multi-hop forwarding paths across both subnets.
Why: Node 4 resides on 10.1.2.0/24, while Node 0 resides on 10.1.1.0/24. When Node 4 sends a packet to 10.1.1.1, its routing table points to Gateway 10.1.2.1 (Node 1), which forwards it out its P2P interface.
csma.EnablePcap ("second", csmaDevices.Get (1), true); What: Enables promiscuous PCAP packet capture on the CSMA bus interface.
Why: The boolean true puts the NIC in promiscuous mode, capturing all frames traversing the shared bus—including packets destined for other nodes!

4.5 Queues, Bufferbloat & Active Queue Management (AQM)

Whenever packets arrive faster than a link's transmission rate, they accumulate in a buffer queue inside the NetDevice.

  • DropTailQueue: Standard First-In-First-Out (FIFO) buffer. When the queue reaches capacity (e.g. 100 packets), all new incoming packets are dropped at the tail. This can cause TCP global synchronization.
  • CoDel (Controlled Delay): Modern Active Queue Management (AQM) that monitors packet queuing delay. If packets sit in the queue longer than 5 ms, CoDel drops packets proactively to signal TCP senders to back off, eliminating bufferbloat.
// Customizing the transmission queue size on a PointToPoint link:
pointToPoint.SetQueue ("ns3::DropTailQueue<Packet>", "MaxSize", QueueSizeValue (QueueSize ("50p")));

5.1 The ns-3 Tracing Subsystem & The Observer Pattern

In many network simulators, extracting metrics requires littering core protocol C++ code with printf or file writing statements. ns-3 avoids this architectural anti-pattern by strictly enforcing the Observer Pattern.

Core simulation models provide Trace Sources (signals that fire when an internal event happens, such as packet dropped or queue full). Independent user code registers Trace Sinks (custom callback functions). The simulator connects them via Config Paths, meaning simulation models remain 100% decoupled from data logging!

#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"

using namespace ns3;

NS_LOG_COMPONENT_DEFINE ("AeroWlanTracingDemo");

// Custom Trace Sink Callback: Invoked automatically whenever a queue drops a packet
static void
SinkPacketDrop (std::string context, Ptr<const Packet> packet)
{
  NS_LOG_WARN ("TRACED DROP at " << Simulator::Now ().GetSeconds ()
               << "s | Context: " << context
               << " | Packet Size: " << packet->GetSize () << " bytes");
}

int main (int argc, char *argv[])
{
  CommandLine cmd (__FILE__);
  cmd.Parse (argc, argv);

  NodeContainer nodes;
  nodes.Create (2);

  PointToPointHelper p2p;
  p2p.SetDeviceAttribute ("DataRate", StringValue ("5Mbps"));
  p2p.SetChannelAttribute ("Delay", StringValue ("2ms"));

  // Restrict queue size to 2 packets to trigger intentional drops for testing
  p2p.SetQueue ("ns3::DropTailQueue<Packet>", "MaxSize", QueueSizeValue (QueueSize ("2p")));

  NetDeviceContainer devices = p2p.Install (nodes);

  InternetStackHelper stack;
  stack.Install (nodes);

  Ipv4AddressHelper address;
  address.SetBase ("10.1.1.0", "255.255.255.0");
  Ipv4InterfaceContainer interfaces = address.Assign (devices);

  // Hooking the Trace Sink to queue drop events via the Config subsystem
  Config::Connect ("/NodeList/*/DeviceList/*/$ns3::PointToPointNetDevice/TxQueue/Drop",
                   MakeCallback (&SinkPacketDrop));

  // STEP: Configure high-rate UDP client to saturate the 2-packet queue
  UdpEchoServerHelper echoServer (9);
  ApplicationContainer serverApps = echoServer.Install (nodes.Get (1));
  serverApps.Start (Seconds (1.0));
  serverApps.Stop (Seconds (10.0));

  UdpEchoClientHelper echoClient (interfaces.GetAddress (1), 9);
  echoClient.SetAttribute ("MaxPackets", UintegerValue (20));
  echoClient.SetAttribute ("Interval", TimeValue (MilliSeconds (5))); // Fast transmission
  echoClient.SetAttribute ("PacketSize", UintegerValue (1024));

  ApplicationContainer clientApps = echoClient.Install (nodes.Get (0));
  clientApps.Start (Seconds (2.0));
  clientApps.Stop (Seconds (10.0));

  // Generate ASCII trace log file
  AsciiTraceHelper ascii;
  p2p.EnableAsciiAll (ascii.CreateFileStream ("tracing-demo.tr"));

  // Generate PCAP packet dumps for Wireshark inspection
  p2p.EnablePcapAll ("tracing-demo");

  Simulator::Run ();
  Simulator::Destroy ();
  return 0;
}

6.3 Canonical Data Collection Script (datacollection-demo.cc)

#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"
#include "ns3/gnuplot.h"

using namespace ns3;

static uint64_t g_totalRxBytes = 0;
static Gnuplot2dDataset g_throughputDataset;

// Trace Sink: Tracks total bytes arriving at destination application
static void
PacketRxSink (Ptr<const Packet> packet, const Address &from)
{
  g_totalRxBytes += packet->GetSize ();
}

// Periodic sampler event: Computes throughput every 1.0 second
static void
SampleThroughput (Time interval)
{
  double throughputMbps = (g_totalRxBytes * 8.0) / (interval.GetSeconds () * 1e6);
  g_totalRxBytes = 0; // Reset counter for next window

  double now = Simulator::Now ().GetSeconds ();
  g_throughputDataset.Add (now, throughputMbps);

  // Re-schedule this sampling function after 'interval'
  Simulator::Schedule (interval, &SampleThroughput, interval);
}

int main (int argc, char *argv[])
{
  CommandLine cmd (__FILE__);
  cmd.Parse (argc, argv);

  NodeContainer nodes;
  nodes.Create (2);

  PointToPointHelper p2p;
  p2p.SetDeviceAttribute ("DataRate", StringValue ("10Mbps"));
  p2p.SetChannelAttribute ("Delay", StringValue ("5ms"));
  NetDeviceContainer devices = p2p.Install (nodes);

  InternetStackHelper stack;
  stack.Install (nodes);

  Ipv4AddressHelper address;
  address.SetBase ("10.1.1.0", "255.255.255.0");
  Ipv4InterfaceContainer interfaces = address.Assign (devices);

  // Setup PacketSink on Node 1 (Receiver)
  uint16_t port = 8080;
  PacketSinkHelper sinkHelper ("ns3::UdpSocketFactory",
                               InetSocketAddress (Ipv4Address::GetAny (), port));
  ApplicationContainer serverApps = sinkHelper.Install (nodes.Get (1));
  serverApps.Start (Seconds (1.0));
  serverApps.Stop (Seconds (10.0));

  // Connect Trace Sink to PacketSink's Rx event
  Config::ConnectWithoutContext ("/NodeList/1/ApplicationList/*/$ns3::PacketSink/Rx",
                                MakeCallback (&PacketRxSink));

  // Setup OnOff Traffic Generator on Node 0 (Sender)
  OnOffHelper onoff ("ns3::UdpSocketFactory",
                     Address (InetSocketAddress (interfaces.GetAddress (1), port)));
  onoff.SetConstantRate (DataRate ("8Mbps"));
  ApplicationContainer clientApps = onoff.Install (nodes.Get (0));
  clientApps.Start (Seconds (2.0));
  clientApps.Stop (Seconds (9.0));

  // Initialize Gnuplot Dataset
  g_throughputDataset.SetTitle ("Throughput (Mbps)");
  g_throughputDataset.SetStyle (Gnuplot2dDataset::LINES_POINTS);

  // Schedule first throughput sampling event at t = 2.0s
  Simulator::Schedule (Seconds (2.0), &SampleThroughput, Seconds (1.0));

  Simulator::Run ();

  // Generate Gnuplot plot file at the end of simulation
  Gnuplot plot ("throughput.png");
  plot.SetTitle ("Instantaneous UDP Throughput over 10Mbps Link");
  plot.SetTerminal ("png");
  plot.SetLegend ("Time (seconds)", "Throughput (Mbps)");
  plot.AddDataset (g_throughputDataset);

  std::ofstream plotFile ("throughput.plt");
  plot.GenerateOutput (plotFile);
  plotFile.close ();

  Simulator::Destroy ();
  return 0;
}

7.1 YansWifiPhy vs. SpectrumWifiPhy & Path Loss Models

Modeling wireless signals requires calculating physical signal-to-interference-plus-noise ratios (SINR):

  • YansWifiPhy: Fast single-carrier physical layer model ideal for basic 802.11a/b/g simulations.
  • SpectrumWifiPhy: Multi-carrier frequency-domain model. Crucial for modern 802.11ax (WiFi 6), 802.11be (WiFi 7), and 802.11bn (WiFi 8), accurately capturing subcarrier interference and OFDMA resource units (RUs).
  • Path Loss Models: Calculate attenuation based on distance $d$ (e.g., FriisPropagationLossModel, LogDistancePropagationLossModel):
\[ P_{\text{rx}}(d) = P_{\text{tx}} - 10 \cdot \gamma \cdot \log_{10}\left(\frac{d}{d_0}\right) - X_\sigma \]
Module 8 802.11 MAC Layer & EDCA QoS
▼

8.1 FrameExchangeManager, RTS/CTS & A-MPDU Aggregation

In ns-3.45, Wi-Fi channel access and handshakes are orchestrated by the FrameExchangeManager:

  • EDCA (Enhanced Distributed Channel Access): Maps packets into 4 Access Categories (AC_VO for Voice, AC_VI for Video, AC_BE for Best Effort, AC_BK for Background) with distinct contention windows ($CW_{\min}, CW_{\max}$) and AIFS timers.
  • A-MPDU Aggregation: Bundles multiple MAC frames into a single physical transmission burst, reducing PHY preamble overhead.
  • BlockAck: Replaces individual ACKs with a single bitmap confirming receipt of dozens of subframes.
Module 9 WiFi 7 (802.11be) Multi-Link Operation (MLO)
▼

9.1 Multi-Link Devices (MLD), STR/NSTR & 320 MHz Channels

The defining innovation of IEEE 802.11be (WiFi 7) is Multi-Link Operation (MLO):

  • Multi-Link Device (MLD): An AP or Station containing multiple physical radios operating simultaneously across 2.4 GHz, 5 GHz, and 6 GHz bands.
  • Simultaneous Transmit and Receive (STR): Enables a device to transmit on Link 1 (e.g. 5 GHz) while receiving data concurrently on Link 2 (e.g. 6 GHz) without self-interference.
  • Non-Simultaneous Transmit and Receive (NSTR): Lower-cost hardware where transmission on one link blinds adjacent bands.
  • Multiple Resource Units (Multi-RU): Assigns punctured or non-contiguous chunks of 320 MHz spectrum to a single client to avoid localized interference.

Configuring WiFi 7 in ns-3:

WifiHelper wifi;
wifi.SetStandard (WIFI_STANDARD_80211be); // EHT Standard

// Configure Multi-Link Device with 2 links:
WifiMacHelper mac;
mac.SetMultiLinkOperation (true);

10.1 Multi-AP Coordination (MAPC) & Deterministic Latency

While WiFi 7 prioritized raw peak data rate (46 Gbps), IEEE 802.11bn (WiFi 8 UHR) focuses on extreme reliability ($99.999\%$) and sub-5ms bounded latency:

  • Multi-AP Coordination (MAPC): Neighboring Access Points synchronize over wired backhauls to schedule transmissions cooperatively, eliminating uncoordinated collisions in dense enterprise spaces.
  • Coordinated Spatial Reuse (CoSR): Dynamically adjusts AP transmit power to allow parallel transmissions without causing destructive interference.
  • Coordinated Beamforming (CoBF): Multiple APs steer spatial nulls toward adjacent stations while beamforming peak energy toward their desired client.
