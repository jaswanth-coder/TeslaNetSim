1.1 Discrete-Event Simulation (DES) vs. Real-World Wall-Clock Time

In everyday programming (such as web servers or game engines), time advances continuously according to the CPU wall-clock stopwatch ($\Delta t = 16.6\text{ ms}$ for 60 frames per second). In contrast, ns-3 is a Discrete-Event Simulator (DES).

⏱️ Visual Flow: Discrete Event Priority Queue & Clock Leaps

Figure 1.1: The event priority queue calendar. When the calendar executes $t=2.002\text{s}$, it immediately leaps forward to the next scheduled event without wasting wall-clock CPU instructions.

  • The Event Calendar: A priority queue $Q$ sorted strictly by timestamp $t$.
  • Zero Idle Latency: If no events are scheduled between $2.002\text{s}$ and $10.0\text{s}$, the simulator advances virtual time instantaneously.

1.2 The Standard 7-Step Simulation Pipeline

Whether you are building a simple 2-node point-to-point link or a 100-node IEEE 802.11be WiFi 7 Multi-Link network, every ns-3 simulation follows seven standardized phases.

🔄 Visual Pipeline: The 7-Step Sequence Flow
1
CLI Argument Parsing CommandLine cmd; cmd.Parse(argc, argv);
Allows overriding simulation parameters directly from the shell terminal without re-compiling C++ source.
2
Node Creation NodeContainer nodes; nodes.Create(2);
Instantiates bare virtual computing hosts managed by intrusive reference counting smart pointers (Ptr<Node>).
3
Device & Channel Configuration PointToPointHelper p2p; NetDeviceContainer dev = p2p.Install(nodes);
Models the physical medium (cable/wireless channel) and installs Network Interface Cards (NICs) on nodes.
4
Protocol Stack Installation InternetStackHelper stack; stack.Install(nodes);
Aggregates ARP, IPv4/IPv6, ICMP, UDP, and TCP protocol engines into each bare node object.
5
IP Address Assignment Ipv4AddressHelper ip; ip.Assign(dev);
Allocates network subnets, sets netmasks, binds IP addresses to NIC interfaces, and configures loopbacks.
6
Application Setup & Scheduling UdpEchoServerHelper / UdpEchoClientHelper
Binds listener sockets on destination ports and schedules traffic generation start and stop events.
7
Execution & Memory Teardown Simulator::Run(); Simulator::Destroy();
Starts the priority queue event calendar loop and cleanly frees cyclic references to prevent memory leaks.

1.4 Exhaustive Line-by-Line Code Breakdown of first.cc

To understand ns-3 properly, every single line of code must be understood from three angles: what it does, why it is necessary, and what happens under the hood in memory. 

#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"

using namespace ns3;

NS_LOG_COMPONENT_DEFINE ("AeroWlanFirstScript");

int main (int argc, char *argv[])
{
  CommandLine cmd (__FILE__);
  cmd.Parse (argc, argv);

  Time::SetResolution (Time::NS);
  LogComponentEnable ("UdpEchoClientApplication", LOG_LEVEL_INFO);
  LogComponentEnable ("UdpEchoServerApplication", LOG_LEVEL_INFO);

  NodeContainer nodes;
  nodes.Create (2);

  PointToPointHelper pointToPoint;
  pointToPoint.SetDeviceAttribute ("DataRate", StringValue ("5Mbps"));
  pointToPoint.SetChannelAttribute ("Delay", StringValue ("2ms"));

  NetDeviceContainer devices;
  devices = pointToPoint.Install (nodes);

  InternetStackHelper stack;
  stack.Install (nodes);

  Ipv4AddressHelper address;
  address.SetBase ("10.1.1.0", "255.255.255.0");

  Ipv4InterfaceContainer interfaces = address.Assign (devices);

  UdpEchoServerHelper echoServer (9);

  ApplicationContainer serverApps = echoServer.Install (nodes.Get (1));
  serverApps.Start (Seconds (1.0));
  serverApps.Stop (Seconds (10.0));

  UdpEchoClientHelper echoClient (interfaces.GetAddress (1), 9);
  echoClient.SetAttribute ("MaxPackets", UintegerValue (3));
  echoClient.SetAttribute ("Interval", TimeValue (Seconds (1.0)));
  echoClient.SetAttribute ("PacketSize", UintegerValue (1024));

  ApplicationContainer clientApps = echoClient.Install (nodes.Get (0));
  clientApps.Start (Seconds (2.0));
  clientApps.Stop (Seconds (10.0));

  Simulator::Run ();
  Simulator::Destroy ();
  return 0;
}
Code Statement Exhaustive Architectural Breakdown (What, Why & Memory Model)
#include "ns3/core-module.h"
...
#include "ns3/applications-module.h"		 What: Includes the master module umbrella headers.
Why: ns-3 is composed of modular libraries. core-module.h imports the event scheduler, timers, and logging. network-module.h imports packets and nodes. internet-module.h imports IPv4/TCP/UDP. point-to-point-module.h imports physical wire helpers. applications-module.h imports traffic generator apps.
Under the Hood: The compiler resolves symbol declarations; during the build phase, CMake links your binary against libns3.45-core-default.so, libns3.45-network-default.so, etc.
using namespace ns3; What: Imports all ns-3 identifiers into the local scope.
Why: All native ns-3 classes reside inside the ns3 namespace. This prevents name collisions between ns-3's Packet and third-party or standard library headers.
NS_LOG_COMPONENT_DEFINE ("AeroWlanFirstScript"); What: Defines a unique string identifier for this simulation script.
Why: Registers this file with the ns-3 logging map. It enables you to activate logging statements (e.g. NS_LOG_INFO("...")) from the terminal at runtime using export NS_LOG="AeroWlanFirstScript=level_all".
CommandLine cmd (__FILE__);
cmd.Parse (argc, argv);		 What: Binds the shell argument parser to argc and argv.
Why: Allows users to pass command-line arguments (e.g. --PrintHelp or --nNodes=5) without altering or recompiling C++ source code.
Under the Hood: Inspects CLI tokens against the registered TypeId attributes of ns-3 classes.
Time::SetResolution (Time::NS); What: Sets the global simulation time resolution to nanoseconds.
Why: The internal simulation clock stores time as a 64-bit integer. Setting the resolution to nanoseconds means virtual time advances in units of $10^{-9}$ seconds, balancing high precision with overflow avoidance.
LogComponentEnable ("UdpEchoClientApplication", LOG_LEVEL_INFO); What: Turns on informational console printouts for the UDP client and server.
Why: Without this, the simulation runs silently in the background and prints nothing to standard output. Enabling LOG_LEVEL_INFO outputs lines like "Sent 1024 bytes to 10.1.1.2" and "Received 1024 bytes from 10.1.1.1".
NodeContainer nodes;
nodes.Create (2);		 What: Creates two bare computing hosts.
Why: Every network needs physical hosts. nodes.Create(2) creates Node 0 and Node 1.
Under the Hood: Instantiates two Ptr<Node> objects via CreateObject<Node>(). At this stage, each node is an empty container with an empty object aggregation list—no NIC, no IP, no protocols installed yet.
PointToPointHelper pointToPoint;
pointToPoint.SetDeviceAttribute ("DataRate", StringValue ("5Mbps"));
pointToPoint.SetChannelAttribute ("Delay", StringValue ("2ms"));		 What: Configures physical layer and link layer parameters.
Why: Models a physical cable between the nodes with a bandwidth limit of 5 Megabits per second and an electromagnetic signal propagation delay of 2 milliseconds.
NetDeviceContainer devices;
devices = pointToPoint.Install (nodes);		 What: Installs Network Interface Cards (NICs) on Node 0 and Node 1 and connects them.
Why: Links cannot transmit data without network cards. Install() creates two PointToPointNetDevice objects, plugs one into Node 0, plugs one into Node 1, attaches them both to a single PointToPointChannel, and adds a transmission queue (DropTailQueue).
InternetStackHelper stack;
stack.Install (nodes);		 What: Installs the Layer 3 and Layer 4 internet protocol stack.
Why: Bare nodes cannot understand IP addresses or UDP packets. stack.Install(nodes) aggregates instances of Ipv4, ArpL3Protocol, TrafficControlLayer, and UDP/TCP protocol managers to each node.
Under the Hood: Now, calling node->GetObject<Ipv4>() will return a valid pointer instead of nullptr!
Ipv4AddressHelper address;
address.SetBase ("10.1.1.0", "255.255.255.0");
Ipv4InterfaceContainer interfaces = address.Assign (devices);		 What: Allocates IP addresses and binds them to network cards.
Why: Assigns subnet 10.1.1.0/24. Device 0 on Node 0 receives 10.1.1.1; Device 1 on Node 1 receives 10.1.1.2.
Under the Hood: Creates an Ipv4Interface object for each device and registers it with the node's aggregated Ipv4 protocol engine.
UdpEchoServerHelper echoServer (9);
ApplicationContainer serverApps = echoServer.Install (nodes.Get (1));
serverApps.Start (Seconds (1.0));
serverApps.Stop (Seconds (10.0));		 What: Installs a UDP Echo Server on Node 1 listening on port 9.
Why: The server acts as the receiver. It begins listening at virtual simulation time $t = 1.0\text{ s}$ and shuts down at $t = 10.0\text{ s}$. Any packet arriving on port 9 is echoed back to the sender.
UdpEchoClientHelper echoClient (interfaces.GetAddress (1), 9);
echoClient.SetAttribute ("MaxPackets", UintegerValue (3));
echoClient.SetAttribute ("Interval", TimeValue (Seconds (1.0)));
echoClient.SetAttribute ("PacketSize", UintegerValue (1024));
ApplicationContainer clientApps = echoClient.Install (nodes.Get (0));
clientApps.Start (Seconds (2.0));
clientApps.Stop (Seconds (10.0));		 What: Configures and installs a UDP traffic generator on Node 0.
Why: Points the client toward Node 1's IP (10.1.1.2) on port 9. It schedules 3 packets, each 1024 bytes in payload, spaced 1.0 second apart, starting at $t = 2.0\text{ s}$.
Simulator::Run ();
Simulator::Destroy ();		 What: Executes the simulation event calendar and cleans up memory.
Why: Simulator::Run() hands execution over to the priority queue loop. Events run until $t = 10.0\text{ s}$. Simulator::Destroy() breaks circular reference loops (e.g. sockets referencing nodes) so that all Ptr<T> counters drop to 0, preventing memory leaks.
Module 2 Conceptual Overview & Core Network Abstractions

2.1 Node, NetDevice, Channel & Object Aggregation

In physical networks, computers plug into network interface cards (NICs), which attach to physical cables. In ns-3, these map directly to C++ abstractions:

  • Node (Ptr<Node>): Represents an empty computing host. It starts completely bare—no IP stack, no MAC layer, no hardware.
  • NetDevice (Ptr<NetDevice>): Models the network interface card (NIC) and Layer 2 framing logic. Examples: PointToPointNetDevice, WifiNetDevice.
  • Channel (Ptr<Channel>): Represents the transmission medium (fiber, twisted-pair cable, or wireless radio propagation environment). A NetDevice plugs into a Channel.
  • Application (Ptr<Application>): Models user-space processes generating and consuming packet traffic (e.g., UdpEchoClient, OnOffApplication).
Tip
 Object Aggregation: ns-3 uses dynamic aggregation (GetObject<T>()) rather than multiple inheritance. When you install an Internet stack, an Ipv4 protocol engine is aggregated into the bare node.

3.1 The NS_LOG Logging Subsystem & CLI Overrides

Printing debug logs using std::cout clutters code. ns-3 includes a granular logging framework controlled via environment variables:

# Enable timestamps and function names for UDP echo components:
export 'NS_LOG=UdpEchoClientApplication=level_all|prefix_time:UdpEchoServerApplication=level_all|prefix_time'
./ns3 run scratch/first

Dynamic Attribute Overrides

Any parameter registered in an ns-3 class TypeId can be overridden directly from the shell without editing source code:

./ns3 run "scratch/first --ns3::PointToPointNetDevice::DataRate=10Mbps"
Module 4 Building Complex Topologies (Bus/CSMA & Star)

4.1 CSMA/Ethernet Bus Topologies (second.cc)

Point-to-point links only connect two nodes. To model shared local area networks (LANs), ns-3 provides the CsmaHelper:

NodeContainer csmaNodes;
csmaNodes.Create (4);

CsmaHelper csma;
csma.SetChannelAttribute ("DataRate", StringValue ("100Mbps"));
csma.SetChannelAttribute ("Delay", TimeValue (NanoSeconds (6560)));

NetDeviceContainer csmaDevices = csma.Install (csmaNodes);

This creates a carrier-sense multiple access bus channel where all 4 nodes share bandwidth and handle packet collision avoidance.

5.1 PCAP Wireshark Captures & Ascii Traces

Simulation results must be verified at the packet level. ns-3 can output industry-standard .pcap captures that open directly in Wireshark:

PointToPointHelper p2p;
// Generates first-0-0.pcap and first-1-0.pcap

AsciiTraceHelper ascii;
p2p.EnableAsciiAll (ascii.CreateFileStream ("first.tr"));

In Wireshark, you can inspect UDP source/destination ports, IP TTL, packet sizes, and round-trip times down to the nanosecond.

7.1 YansWifiPhy vs. SpectrumWifiPhy & Path Loss Models

Modeling wireless signals requires calculating physical signal-to-interference-plus-noise ratios (SINR):

  • YansWifiPhy: Fast single-carrier physical layer model ideal for basic 802.11a/b/g simulations.
  • SpectrumWifiPhy: Multi-carrier frequency-domain model. Crucial for modern 802.11ax (WiFi 6), 802.11be (WiFi 7), and 802.11bn (WiFi 8), accurately capturing subcarrier interference and OFDMA resource units (RUs).
  • Path Loss Models: Calculate attenuation based on distance $d$ (e.g., FriisPropagationLossModel, LogDistancePropagationLossModel):
\[ P_{\text{rx}}(d) = P_{\text{tx}} - 10 \cdot \gamma \cdot \log_{10}\left(\frac{d}{d_0}\right) - X_\sigma \]
Module 8 802.11 MAC Layer & EDCA QoS
▼

8.1 FrameExchangeManager, RTS/CTS & A-MPDU Aggregation

In ns-3.45, Wi-Fi channel access and handshakes are orchestrated by the FrameExchangeManager:

  • EDCA (Enhanced Distributed Channel Access): Maps packets into 4 Access Categories (AC_VO for Voice, AC_VI for Video, AC_BE for Best Effort, AC_BK for Background) with distinct contention windows ($CW_{\min}, CW_{\max}$) and AIFS timers.
  • A-MPDU Aggregation: Bundles multiple MAC frames into a single physical transmission burst, reducing PHY preamble overhead.
  • BlockAck: Replaces individual ACKs with a single bitmap confirming receipt of dozens of subframes.
Module 9 WiFi 7 (802.11be) Multi-Link Operation (MLO)
▼

9.1 Multi-Link Devices (MLD), STR/NSTR & 320 MHz Channels

The defining innovation of IEEE 802.11be (WiFi 7) is Multi-Link Operation (MLO):

  • Multi-Link Device (MLD): An AP or Station containing multiple physical radios operating simultaneously across 2.4 GHz, 5 GHz, and 6 GHz bands.
  • Simultaneous Transmit and Receive (STR): Enables a device to transmit on Link 1 (e.g. 5 GHz) while receiving data concurrently on Link 2 (e.g. 6 GHz) without self-interference.
  • Non-Simultaneous Transmit and Receive (NSTR): Lower-cost hardware where transmission on one link blinds adjacent bands.
  • Multiple Resource Units (Multi-RU): Assigns punctured or non-contiguous chunks of 320 MHz spectrum to a single client to avoid localized interference.

Configuring WiFi 7 in ns-3:

WifiHelper wifi;
wifi.SetStandard (WIFI_STANDARD_80211be); // EHT Standard

// Configure Multi-Link Device with 2 links:
WifiMacHelper mac;
mac.SetMultiLinkOperation (true);
Module 10 WiFi 8 (802.11bn) Ultra High Reliability (UHR)
▼

10.1 Multi-AP Coordination (MAPC) & Deterministic Latency

While WiFi 7 prioritized raw peak data rate (46 Gbps), IEEE 802.11bn (WiFi 8 UHR) focuses on extreme reliability ($99.999\%$) and sub-5ms bounded latency:

  • Multi-AP Coordination (MAPC): Neighboring Access Points synchronize over wired backhauls to schedule transmissions cooperatively, eliminating uncoordinated collisions in dense enterprise spaces.
  • Coordinated Spatial Reuse (CoSR): Dynamically adjusts AP transmit power to allow parallel transmissions without causing destructive interference.
  • Coordinated Beamforming (CoBF): Multiple APs steer spatial nulls toward adjacent stations while beamforming peak energy toward their desired client.

11.1 Intrusive Reference Counting (SimpleRefCount)

ns-3 avoids manual delete using intrusive reference counting:

// Create an object with reference count = 1:
Ptr<Node> n = CreateObject<Node>();

// Pass to container (increments reference count):
NodeContainer c;
c.Add(n); // Ref count = 2

// When 'n' goes out of scope, reference count drops back to 1.
// When 'c' is destroyed, reference count drops to 0 and memory frees automatically!
