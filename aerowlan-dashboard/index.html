💻 Step-by-Step ns-3 & Linux Simulation Workflow Guide

Step 1: Configuration & CMake Initialization

Before compiling any scripts, you must configure the build environment. This sets compilation flags, enables optional modules, and turns on examples/tests:

./ns3 configure --enable-examples --enable-tests --build-profile=debug
  • --build-profile=debug: Enables compiler debugging assertions and symbols (essential for troubleshooting segmentation faults).
  • --build-profile=optimized: Removes debug features to enable 5x-10x faster execution for massive trace collection.

Step 2: Compiling Your Simulation

Compile the whole codebase or register new files placed in the scratch/ directory:

./ns3 build

If you modify a header file in a core module (like src/wifi/model/wifi-phy.h), this command will automatically compile only the affected modules and update dependencies.

Step 3: Running a Script with Custom Arguments

Execute your compiled simulation. To pass command-line arguments to the script, append them after the double-dash (--):

./ns3 run "scratch/aerowlan_exercises/hello-ns3 --argName=val"

Step 4: Debugging with ns-3 Logging System

Enable verbose execution logs from specific components dynamically using the NS_LOG environment variable. You can target specific layers:

export NS_LOG="UdpEchoClientApplication=level_all:WifiPhy=level_info"

Common logging levels: error, warn, info, debug, logic, all. To clear logging rules, run: unset NS_LOG.

Step 5: Collecting & Analyzing Network Traces (PCAPs)

Many simulation scripts support trace file generation (enabled via code configurations or run-time flags). To capture standard PCAP packets:

./ns3 run scratch/aerowlan_exercises/simple-wifi -- --pcap=1

To read the generated packet capture files on your Linux console, use tcpdump:

tcpdump -nn -tt -r simple-wifi-0-0.pcap

Step 6: Cleaning the Build Directory

If you encounter linking conflicts or CMake cache corruption, clean the build directory before re-configuring:

./ns3 clean
